# v2ray 线路保护

适用于 ENGE SPX 0.5.0 Preview。工作区的最终出口与“如何连接落地代理”是两项不同的检查。

## 推荐：软件内双跳

1. 在 v2ray 中复制线路节点的分享链接，使用 ENGE SPX 的批量导入。导入会追加节点，保留已有落地和当前落地选择。
2. 在上方“落地代理”选择 SOCKS5、HTTP 或 HTTPS 落地。在“前置线路保护”启用线路，选择“软件内双跳（推荐）”，再单独选择加密线路节点。
3. 如果线路地址是域名，填写该服务器的 IPv4，可从服务商或客户端连接信息获取。这里填的是线路服务器地址，未必等于线路的上网出口。软件不会自动查询宿主机 DNS，也不会把原 TLS 名称改成这个 IP。
4. 如果已知道线路上网出口，填入“锁定线路出口 IPv4”；不知道可留空，在首次检查结果中人工核对。
5. 保存并检查。软件先通过线路单独核对两个出口来源，再通过完整双跳核对落地出口。任一检查失败就停止。
6. 确认线路出口、落地出口与时区后启用。确认时会重新检查，运行期间继续监测；不自动接受变更后的出口。

| 字段 | 指什么 |
| --- | --- |
| 线路服务器 IPv4 | 客户端连接的加密线路服务器，用于启动固定第一跳 |
| 线路出口 IPv4 | 经过第一跳访问检测服务时，对方看到的来源地址 |
| 落地出口 IPv4 | 经过完整双跳访问目标服务时，对方看到的来源地址 |

软件内双跳直接配置加密线路的协议、认证和固定端点。落地连接必须经过它，没有 DIRECT、自动测速组或故障转移组作为备用。外部 v2ray 的分流规则不能让这条应用内链路跳过已配置的第一跳。

支持 SS AEAD / 2022、Trojan TCP/TLS、VLESS TCP/TLS、加密 VMess AEAD TCP 和 HTTPS 第一跳。普通 HTTP 和 SOCKS5 可作落地，不能作此模式的加密线路。WS、gRPC、Reality、XTLS、uTLS 等当前未支持的分享参数会被拒绝；不会删除这些参数后尝试直连。

线路服务商能够看到你与它建立连接，并决定服务器侧如何出网；该模式不能约束服务商、不保证匿名，也不能抵御宿主机被控制。宿主机的系统级 TUN 仍可能改变到线路服务器的外层路径，但应用配置要求的加密第一跳仍须成功建立。

## 兼容：继续使用现有 v2ray 本机代理

1. 保持 v2ray 运行，查明它的 HTTP 或 SOCKS 回环监听地址。无需开启 LAN 访问。
2. 选择“本机代理（v2ray 兼容）”，填写地址；也可读取 Windows 系统代理。该操作不修改系统代理或执行 PAC。
3. 选择落地，点击“导出 v2rayN 防直连路由规则”。文件只包含落地目的地址、端口、检测服务域名和 proxy 路由标记，不包含节点密码。
4. 在 v2rayN 的自定义路由中导入，并置于直连规则之前。确保其 `proxy` 出口指向指定线路，涉及的嵌套策略也不含直连回退。不同 v2ray 客户端的导入方式可能不同。
5. 保存、检查并核对两个出口。可填写预先知道的线路出口，避免第一次检查就接受错误出口。

导出格式参考 [v2rayN 自定义路由说明](https://github.com/2dust/v2rayN/wiki/Description-of-custom-routing-rules)。本软件不自动编辑 v2ray 的数据库、订阅或全局设置。

兼容模式使用本机代理建立到落地的连接，落地域名交给该代理，不由 ENGE SPX 预先解析。线路诊断也经过同一代理，但诊断的目的地是 IP 检测服务；外部客户端可以对不同目的地采用不同规则。**检测服务显示正确线路 IP，不能单独证明落地连接也走该线路。** 首次检测已经直连、但未填写预期出口时，也不能自动区分。软件内双跳用于消除对这个外部分流行为的依赖。

## 工作区与检查入口

工作容器继续只连接内部网络，通过落地代理出网。独立线路检查入口只监听网关自身的 `127.0.0.1:2082`，由宿主机通过 Docker exec 调用。工作容器不能连接这个入口来绕过落地。线路诊断不需要在宿主机上主动直连查询“真实 IP”。

确认后的线路出口不符时，软件先拒绝继续连接落地，再停止本环境，保留明确的线路错误原因。落地出口变化也会停止。IP 变化检测仍有约 30 秒间隔与请求超时，不承诺瞬间检测；固定链路故障时没有自动直连备用路径。

## 下载与 DNS 范围

运行环境和 HTTPS 订阅的下载使用独立的本机下载代理。勾选代理下载时，缺少代理或代理连接失败都不会自动退回直连；主动取消该选项才允许直连。订阅重定向降为 HTTP 时拒绝继续，并限制解压后的响应大小。

下载不通过工作区落地；源码构建的镜像拉取属于 Docker Desktop 自己的网络。这些流量不应被视为已通过工作区双跳。软件内双跳需要填写第一跳服务器 IPv4；启用前置线路后，落地域名经第一跳处理。未启用前置线路的单落地模式仍使用本机解析节点地址。

从旧版升级后需要重新检查并确认连接，旧的确认结果不能沿用为新的线路保护证据。匹配的镜像、项目容器和账号、浏览器数据卷继续复用。
