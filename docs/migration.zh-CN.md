# 旧版 Windows 环境迁移到 ENGE SPX

新安装使用 ENGE SPX 的程序名、快捷方式、设置目录、容器名和协议标识。为了继续使用此前 Windows 0.1 / 0.2 的资料，升级路径保留必要的兼容标识。

1. 在旧版停止环境，退出旧窗口；旧版关闭窗口后可能仍有后台监测，程序会在首次检查时等待交接。
2. 安装 ENGE SPX，或完整解压免安装包。新 GUI 为 `ENGE-SPX.exe`，CLI 为 `spx.exe`。
3. 如果 `%LOCALAPPDATA%\ENGE-SPX` 尚未初始化、旧目录 `%LOCALAPPDATA%\EgressWorkbenchWindows` 有有效实例记录，程序继续使用旧目录，不移动它。自定义目录通过 `--data` 指定。
4. 镜像配方匹配的旧环境继续使用原镜像 ID 和容器资源标识。安装入口不会只因品牌变化而重建项目容器、丢弃其可写层或改写已有镜像标签。
5. 重新检查落地出口并确认，之后再启动工具。首次接管旧后台监测最多约 40 秒。若旧进程未退出，程序保留停止状态并提示重试。

工具账号、项目会话、浏览器资料仍保存在原 Docker 数据卷。需要新浏览器镜像时，会在旧浏览器停止后迁移该卷内的 profile 目录，保留原内容。旧版 0.2 的镜像配方和浏览器协议有明确兼容记录；不识别的镜像不会伪装为兼容。

在旧目录运行时，Docker 资源中的旧前缀和兼容协议可能仍存在，这是保留已有数据的需要。全新环境使用 `spx-<实例标识>` 和 `io.enge.spx.*` 标签；这些名称与 Windows 安装目录独立。

更换 IANA 时区、迁移到另一台机器或从原版 macOS 环境迁移，不属于这次自动兼容范围。备份私有目录、Docker 数据和真实项目后，再安排单独迁移。
