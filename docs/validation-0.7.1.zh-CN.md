## 处理的问题与已知边界

0.7.0 发布后，用户反馈启动会自动唤起 Docker Desktop，随后界面无报错窗口
退出。当前尚未取得该电脑的故障堆栈，不能将所有无提示退出认定为同一个根因。

0.7.1 移除了 Python 层的 Win32 WNDPROC 替换，保持 Tk 原有窗口过程，
保留黑黄界面、自定义标题栏、任务栏和窗口控制；缩放改由八个自定义边缘处理。
原生检查确认窗口过程地址没有被替换，并核对窗口样式和最大化区域。

排查也发现旧构建脚本用 `py -3` 选择其他已安装 Python，实际打包版本与
源码测试的 Python 3.12 不同。现在 CI 明确传入受测解释器的完整路径，
并检查打包程序自检报告的实际运行时为 **Python 3.12.10**。有多个 Python
安装时，构建脚本只选择一个完整路径；版本不符的生成环境会重建。

这些检查补齐了此前“单独显示界面”和“单独启动假 Desktop”的组合覆盖，
仍不能代替用户的真实 Docker Desktop / WSL、显示器、DPI、v2ray 和 Pebrel
组合验收。新版保留本地故障记录，便于继续定位尚未复现的实机退出。

## 本机故障日志

应用数据目录的 `logs/gui.log` 记录生命周期、Docker 检测状态与异常位置；
`logs/gui-fault.log` 记录故障处理器可捕获的底层堆栈。日志仅存本机、限制大小，
不自动上传，不包含异常消息、帧内变量或完整节点配置。系统强制结束、断电或
Python 初始化之前的异常可能没有堆栈。

使用方法和数据迁移后的查找位置见 [安装排障](installation-troubleshooting.zh-CN.md)。
隔离范围、共享项目、共享账号、Chromium `--no-sandbox` 和监测周期等边界
继续适用，见 [安全模型](security-model.zh-CN.md)。
