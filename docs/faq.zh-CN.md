# 常见问题

本页解释 ENGE SPX 的用途、工作区边界和常见使用选择。首次使用请先看 [快速入门](quickstart.zh-CN.md)，安装错误见 [安装排障](installation-troubleshooting.zh-CN.md)。

## 这是一个做什么的软件

ENGE SPX 是 Windows 上的 AI 编程隔离工作台。它把 Claude Code、Codex 和 Chromium 放入 Linux 容器，由桌面界面准备环境、管理代理路径、核对出口并打开项目工具。你继续使用本机项目目录与自己的终端，工具命令在容器里执行。

它不提供 AI 账号、订阅或代理节点；代理链路也不能保证加速、匿名或账号一定被服务商接受。

## 工作区是 Windows 系统吗

不是。Windows 运行控制端与终端窗口，Docker Desktop 的 Linux / WSL 2 后端运行容器。容器中的命令、路径和依赖遵循 Linux 行为；本机项目通过共享挂载供工具读写。

它不启动一套单独的 Windows 桌面虚拟机。容器与独立虚拟机的隔离边界不同，详见 [安全模型](security-model.zh-CN.md)。

## 我已有 v2ray 线路，能否只增加 SOCKS5 落地

可以。

- 分享链接符合当前支持范围时，可导入线路，选择“软件内双跳”，让软件固定第一跳与 SOCKS5 / HTTP / HTTPS 落地。域名线路需提供服务器 IPv4，TLS 名称与证书校验保留。
- 想保留现有客户端，或线路使用未支持的传输方式时，选择“本机代理（v2ray 兼容）”，填写实际 HTTP / SOCKS 回环监听地址，再选落地。外部客户端仍负责到落地的路由，需要确保相关目标不被分流为 DIRECT。

两种方式都会检查出口，但兼容模式不能通过某个检测服务的 IP，证明所有目标都使用相同路径。详见 [线路保护](line-protection.zh-CN.md)。

## 可以同时在本机使用 v2ray 吗

可以。ENGE SPX 不自动修改 Windows 系统代理或 v2ray 配置。软件内双跳直接配置所选线路；兼容模式则调用本机代理。

如果本机开启系统级 TUN，它仍可能影响到线路服务器的外层网络路径。工作区中的“固定第一跳”不代表绕过了宿主机网络栈，也不能约束服务商在服务器端的行为。

## 如果宿主机直连，工作区一定会跟着直连吗

不能只根据宿主机 IP 判断工作区路径，需要区分配置模式。

软件内双跳要求固定的加密线路连接成功，再访问落地；配置中没有直连或故障回退作为备用。工作容器使用内部网络和受控网关，不能只因为宿主机能直连，就自动改用该直连路径。

兼容模式仍受外部客户端按目标分流的影响；关闭前置线路时，本机会连接落地，单落地模式也不提供固定加密第一跳的保护。出口监测有周期和超时，不能承诺瞬时发现所有变化。宿主机被控制、容器逃逸或配置被外部篡改，属于另外的信任边界。

## 工作区和我的电脑完全隔离吗

不是。它减少默认共享的文件与日常浏览器资料暴露，并给工作区设置受控网络，但仍依赖宿主机、Docker 和 WSL。

默认共享模式的项目为读写，可显式授权只读。只读仍允许工具读取项目内密钥，读写允许修改或删除真实文件。不要把整个用户目录或磁盘当成项目共享，重要项目应使用版本管理和备份。0.8.3 起 Chromium 强制验证 user namespace 和 Seccomp-BPF 沙箱，失败拒绝启动；仍不能将容器当成可运行任意恶意网页或程序的专用安全沙箱。

完整范围见 [隔离与安全模型](security-model.zh-CN.md)。

## 不同项目会共享登录账号吗

默认共享和同一身份内会共享。0.11.0 可在“项目工作区”新建独立身份并显式绑定项目，工具 HOME、浏览器 Profile 和下载分开保留；首次需要重新登录，不复制旧凭据。切换身份先停止核验，切换项目本身不会自动更换登录身份。见 [身份与恢复](workspaces.zh-CN.md)。

如果还需要分开节点、时区与整个实例，可继续使用独立数据目录，例如：

```powershell
.\spx.exe --data D:\ENGE-SPX\profile-a gui
.\spx.exe --data D:\ENGE-SPX\profile-b gui
```

首次创建各数据目录会生成各自的安装标识与 Docker 资源名称；匹配资源可按各自记录复用。不要复制带有相同 `instance.json` 的目录来冒充一个新身份。同一数据目录有单窗口控制，不同数据目录使用各自的窗口标识；请分别确认各自的配置和出口。这也不能替代宿主机或服务商侧的身份隔离。

## 为什么我选了代理，下载还要另外设置

工作区链路用于容器中的工具和浏览器；运行环境与订阅下载发生在准备阶段，下载时完整工作区链路可能还没有建立。因此下载使用单独选择的本机代理。

勾选代理下载时，找不到代理或代理连接失败就停止，不自动转直连；要直连下载，需要主动取消该选项。源码构建的镜像拉取使用 Docker Desktop 自己的网络。

## 首次使用是否还要自己启动 Docker

安装和初始化 Docker Desktop 需要完成一次，包括它的许可、WSL 或系统提示。之后打开 ENGE SPX 只检测状态；由你点击“一键准备环境”或“启动并检测”，软件才会启动已安装的 Desktop 并等待 Linux 引擎就绪。一键准备继续衔接镜像核验、缺失环境安装和连接检查。

软件不会自动安装 WSL、重启系统、切换全局 Docker 上下文或替你确认变更后的出口。旧版的打开软件自动启动选项不再生效。

## 刚确认连接就打开 Claude / Codex，会与后台检查冲突吗

启动工具和浏览器时，如果后台连接监测短暂占用环境，程序会自动等待，
无需再次点击。等待最长 30 秒，操作仍在后台执行；拿到操作锁后重新核对
连接，检查通过才准备项目并打开工具。终端和浏览器复用同一次准备结果，
避免启动后再次抢占操作锁。超时或连接异常仍会提示，不会跳过检查。

## 窗口由第三方终端打开，工具还在容器里吗

是。Windows Terminal、PowerShell 或你选择的第三方终端负责显示与交互，启动命令仍通过 Docker 进入所选项目的 Linux 容器。详情见 [终端设置](storage-terminal.zh-CN.md)。

## 不操作 Shell，浏览器环境会自动停止吗

没有 Shell 空闲计时。后台监测独立于 Shell 和主窗口运行；连接保持有效时，
它会持续续期，没有固定挂机时长上限。180 秒是停止续期后的网关保护期限，
不是每三分钟结束一次会话。Windows 上曾因 Docker 读取 `lease.json` 时拒绝文件替换，
导致监测进程退出、租约随后到期。0.8.2 的新网关改用追加式续期记录，
同时给其它 JSON 文件的短暂占用加重试，监测遇到 I/O 错误也不会立即退出。

持续写入失败、睡眠、引擎停止、出口或拓扑变化仍会使环境停止。不会通过
无限延长租约来维持连接。查看数据目录的 `guard.log` 和总览停止原因定位。

## 双跳或远程浏览器的速度损耗能完全消除吗

线路与落地之间的往返、加密及 Docker 显示转发会带来开销，实际带宽也取决于
节点、路由和主机。0.8.2 减少重复容器创建与地理查询，隔离本机代理转发中
各连接的背压，并让显示短暂断线后重连。这些修改减少软件开销，不承诺固定
提速比例；远程画面流畅度也不等同于容器里的下载速度。

## 浏览器和终端会暴露中文字体吗

0.8.2 的新浏览器镜像不再预装 `fonts-noto-cjk`，保留常用西文字体和 Emoji。
部分中文网页可能缺字，网站自行加载的 Web 字体仍可能包含中文。
只移除 CJK 字体不表示无法通过其它特征识别或关联浏览器。

项目容器没有专门安装 CJK 字体包，UTF-8 环境保持原样。Windows 终端负责
绘制中文，容器工具通常无法枚举 Windows 字体目录；但输入的中文、终端类型
及语言设置仍可被工具看到，个别终端还支持字体查询指令。
参见 [Windows 终端协议说明](https://learn.microsoft.com/en-gb/windows/console/classic-vs-vt)
和 [xterm 字体查询控制](https://invisible-island.net/xterm/manpage/xterm.html)。

此次更新需要获取新的网关和浏览器镜像；已有匹配的项目镜像、项目容器、
工具账号卷与浏览器 profile 可以保留，无需删除 Docker 数据。旧版镜像在
更新前仍有原来的字体配置。

## 迁到 D 盘之后，C 盘就不会再占空间吗

应用数据、Docker 数据盘和程序安装目录是不同位置。

应用数据迁移会移动配置、日志和下载缓存，LocalAppData 仍保留很小的位置记录。Docker 的镜像、容器和数据卷需要通过数据盘迁移助手，在 Docker Desktop 中应用 Disk image location 变更；项目原目录和程序目录单独管理。Windows、WSL、Docker Desktop 自身仍可能在系统盘保留组件或其他数据，不能承诺 C 盘零占用。

具体步骤和恢复见 [存储设置](storage-terminal.zh-CN.md)。

## 关闭窗口或者卸载，会删除项目吗

关闭窗口后，已确认的环境与监测进程继续运行。结束工作请先点击“停止环境”或执行 `spx stop`；停止不会关闭整个 Docker Desktop 或其他项目的容器。

停止和卸载不会主动删除项目、私有数据或 Docker 数据卷，但手工清理 Docker / WSL、删除卷或丢失磁盘会影响数据。账号恢复可能需要私有目录与 Docker 数据，项目也应单独备份。

## 支持哪些平台和协议

当前提供 Windows x64 安装版和便携版，预构建运行环境为 Linux amd64。源码需要 Python 3.12+ 和 Tk；ARM64 容器可走源码构建，当前没有 Windows ARM64 安装包。

落地支持 SOCKS5 / HTTP / HTTPS；软件内线路支持当前导入器接受的加密协议组合。WS、gRPC、Reality、XTLS、uTLS 等未支持参数会拒绝，不会删除参数后尝试连接。具体限制以 [代理配置](proxies.zh-CN.md)为准。

## 怎么报告问题

先查看 [安装排障](installation-troubleshooting.zh-CN.md)与 [支持指南](../SUPPORT.md)。总览页可以复制诊断摘要；自行附加日志和截图前，仍需检查并删除凭据、订阅、项目路径与真实出口 IP。

漏洞按 [安全报告说明](../SECURITY.md)处理，避免在普通 Issue 中公开敏感内容。
