# 有界 HTTPS 速度测量

0.13.0 提供按需测量，保留原“网络环境检查”。普通检查、打开软件或资源页都不会自动测速。

## 使用

先启动工作区、核对两级出口并确认连接，再打开 **网络检查 → 测试 HTTPS 速度**。结果可通过“导出测速报告”保存；导出只保存本次缓存，不重新请求网络，也不上传报告。

```powershell
spx network-test
spx network-test --output D:\Reports\spx-network-performance.json
```

命令只接受输出文件，不接受自定义目标、代理或凭据。工作区未确认时返回 `not_ready`，不启动 Docker、浏览器或工作容器。GUI 真正退出会等待当前测量收尾，再执行原有工作区停止和可选 Desktop 联合关闭。

## 流量、时间与对象

测量只在已审计的 session 中，经既有最终网关和所选固定代理链路连接 `https://speed.cloudflare.com/__down`。不增加第一跳测速入口，不从 Windows 主机直连测试，不跟随重定向，不自动换服务或线路。

| 测量请求 | 次数 | 单次请求载荷 |
| --- | ---: | ---: |
| 新建 HTTPS 连接的首字节观察 | 2 | 1 KiB |
| 单次下载 | 1 | 1 MiB |

共请求 1,050,624 B 应用载荷；为检测超量响应，每次最多额外读 1 B。HTTP/TLS/TCP 开销和前后出口复核流量另计。只下载，不做上传测试；固定目标服务仍能观察最终公网出口和 HTTPS 请求，没有发送账号、项目、AI 输入或测速结果遥测。

测量子进程总预算 15 秒，两次小请求各最多 4 秒、下载最多 10 秒，并受剩余总预算限制。**前后的出口/拓扑复核另需时间**，所以整个操作不承诺在 15 秒完成。较慢连接可能读不完 1 MiB，此时显示不完整、已读字节与用时，不能当作零带宽。

## 怎样理解结果

- **HTTPS 首字节耗时**包含连接内部网关、代理 CONNECT、TLS 和目标服务响应；两次样本报告中位数，属于离散观察，不是 ICMP/TCP RTT、丢包率或长期延迟分布。
- **单次请求有效下载 Mbps**按已完成响应字节数与完整请求用时计算，包含建连等开销；另提供正文阶段速率。正文阶段太短时不计算速率。1 Mbps = 1,000,000 bit/s，不等于 1 MB/s。
- **第一跳/最终出口复核耗时**仍是既有多次 HTTPS 核验；它和测速首字节含义不同，不能相减推断某一跳损耗。
- 小响应、服务器限速、缓存和当前负载都会影响结果；不能据单次结果断言线路上限、真实 Claude/Codex 请求速度、noVNC 流畅度或全机性能。

前后出口检查验证其各自服务看到的地址；测速服务观察到的地址没有单独返回核验。路径约束来自既有网关配置，服务商自身的动态路由/分流仍属于信任边界。

## 状态和失败

| 状态 | 含义 |
| --- | --- |
| `checked` | 三次测量完成，前后出口和拓扑复核通过；不代表匿名或所有目的地都经过同一公网地址 |
| `partial` | 目标拒绝、限流、超时或数据不可用，但后续连接复核通过；缺失速率为 null，不是 0 |
| `stale` | 期间会话、策略、确认或容器变化；结果丢弃，不按旧测量停止替换后的会话 |
| `not_ready` | 工作区未确认，未进行测试 |
| `failed` | TLS 证书或前后连接/拓扑验证失败，已请求停止本实例；`stop.verified` 标明是否取得完整停止证据 |

CLI 的 `checked` / `not_ready` 返回 0，其它结果返回 2。TLS 证书/名称验证始终启用；请求失败不允许直连、切换备用节点、关闭沙箱或跳过证书。传输阶段释放操作锁让 guard 继续运行，测量不替代安全监测。

报告只保留白名单数值和固定错误类别，不保存响应体、Cookie、证书原文、原始异常、节点/项目路径或凭据；容器与地址采用每份报告独立的代号。新任务失败不会把旧成功报告当作本次结果。

实测与限制见 [交付验证](validation-network-measurement.zh-CN.md)，长期使用的采集方法见 [Windows 验收](windows-acceptance.zh-CN.md)。
