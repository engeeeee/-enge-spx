# 独立工作区身份与项目授权

第四批开发分支实现；已发布的 0.10.0 仍使用默认共享模式。功能通过完整回归并发布后，版本号与下载以 Releases 为准。

## 选择身份

在“项目工作区”选择项目，然后选择身份与目录权限，点击“应用身份与授权”。应用前先保存工作：切换会停止当前实例的工具、浏览器和网络，随后需要重新检查并确认出口。只在下拉框中选择不会切换运行身份。

- **默认共享（兼容旧版）**：继续使用原有 Claude/Codex 账号、Chromium Profile 和下载资料，不复制、不清空数据。没有新配置文件时，旧版项目和数据卷名称保持原样，项目继续读写。
- **新建身份**：从空白账号和浏览器资料开始，首次需要重新登录。每个身份拥有独立工具 HOME、浏览器 Profile 和下载卷，Cookie、Local Storage、缓存和授权状态分别保留。
- **项目授权**：独立身份必须显式绑定到项目；尚未绑定的项目不能直接启动工具，也不会继承其它身份。每个项目记住上次明确应用的身份及只读/读写权限。

同一个身份内的项目仍共享该身份的工具账号和浏览器资料。如果希望两个项目使用不同账号，请分别创建身份并绑定。一次只启用一个身份，不增加完整虚拟机或同时常驻多套环境；停止的容器及数据卷保留，切换回来复用自己的账号与可写层。

## 只读与读写

“只读项目”禁止向挂载项目目录写入，工具仍能保存本身份的登录资料、缓存和临时文件；需要修改代码时显式选择“读写项目”并应用。只读要求递归只读，Docker/内核不支持时拒绝启动，不自动降级成读写。

切换访问模式会使用单独的项目容器，保留旧容器的可写层，不覆盖或删除它。项目文件本身仍位于原宿主目录。选择本地磁盘的具体目录，不要共享磁盘根目录、用户主目录或应用数据目录。

身份隔离不会隐藏项目文件中的密钥：**只读允许读取；同一项目目录的内容仍然共享。** 写入项目的账号、API Key、脚本、项目级工具配置等可被获准读取该目录的身份看见。宿主管理员与 Docker 管理者仍可访问数据，这不是不同内核的虚拟机或匿名保证。

## 命令行

```powershell
spx profiles list
spx profiles create "个人项目"
# 使用创建结果中的 profile ID，以下以 012345abcdef 为示例
spx --project D:\Projects\Example profiles apply 012345abcdef --access ro
spx check
spx confirm
spx --project D:\Projects\Example codex
spx profiles restore
```

`create` 不会自动切换或复制账号。`profiles select ID` 只切换浏览器/工作区身份，不改变项目绑定；工具启动前仍检查项目授权。`restore` 恢复上次身份选择和授权，保留全部已创建身份的资料引用；不会删卷或账号。

## 配置、迁移与回滚

`workspace-profiles.json` 为 schema=1，包含身份 ID/显示名、当前身份及项目 hash 对应的身份/权限。它不保存代理密码或账号凭据；账号留在对应 Docker 数据卷。`workspace-profiles-state.json` 记录功能已初始化，之后配置丢失、空值或未知版本都会拒绝启动，不会默默回到共享账号。

每次有效配置变更前，将上一份有效公开配置保存为 `workspace-profiles-previous.json`。停止核验失败时不切换，文件写入失败时保持已停止状态，原账号与项目数据保留。可使用“恢复上次”或 `spx profiles restore` 显式恢复；不要删除配置文件尝试重置身份。

降级到旧版前，先明确把需要的项目应用为默认共享/读写，检查后停止工作区，再退出软件并安装旧版。旧版只识别原共享资料，无法管理独立身份；新身份的数据卷保留但旧版不会显示。再次升级后仍通过新版本配置管理。不要在工作区运行时混用旧版 CLI。

Windows DPAPI 仍保护应用代理配置；工作区账号/Profile 卷不在该加密范围。跨盘迁移继续保留实例标识和身份配置，数据卷仍由 Docker Desktop 管理。资源预算继续按项目生效，不把多个身份的资料复制进同一 HOME。
