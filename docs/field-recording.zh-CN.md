# 实机性能记录

0.12.0 提供用户主动开启的记录工具，用于自己的 Windows/WSL2 和真实任务。它不会代替实际运行任务，也不把 CI 合成活动当作实机验证。

## 界面操作

1. 打开“资源与性能 → 实机记录”，选择 1、5、15 或 60 分钟及活动标签。
2. 点击“开始记录”，选择可写位置，例如 `D:\Reports\spx-codex.json`。
3. 像平时一样使用 Claude Code、Codex 或 Chromium；也可以停止工作区，观察资源回收。
4. 到期自动保存，或点击“停止并保存”。可用“导出最近结果”再次导出内存中保留的最近报告。

打开软件或资源页都不会自动开始记录。活动标签由你选择，软件不检查实际 AI 命令或输入，不能以标签证明某模型任务已运行。记录期间其它工作区操作可继续；记录与普通概览共享单一采样通道，不重叠查询。

X 仍隐藏到托盘，**只有已经主动开始的记录会在托盘继续**。真正退出默认先停止工作区，取消记录并等待保存，再关闭界面。迁移应用数据前自动结束记录、关闭文件，再检查迁移，不留下写文件的线程。

## 命令行

```powershell
spx resources --record D:\Reports\spx-workload.json --seconds 900 --interval 10 --activity codex
```

`--seconds` 为 5–3600，`--interval` 为 5–60 秒。查询是串行的，间隔在查询结束后等待，实际时点以报告为准。进度输出到 stderr，最终摘要输出到 stdout；Ctrl+C 保存已采集结果并返回 130。

默认只使用本实例已核验的公开上下文记录；没有记录时仅采集主机/进程，容器标为不可用，不猜测 daemon。也可显式加 `--docker-context desktop-linux`（或自己的本机上下文名），查询前仍检查本机 IPC。采样目标不创建完整工作区 Engine，不读取/解密节点、代理设置或运行令牌。

可用标签：`unspecified`、`gui_idle`、`workspace_idle`、`claude`、`codex`、`browser`、`stopped`。CLI 的控制进程计数属于记录器自身，不是未登记的 GUI；界面记录则测量运行它的 GUI 进程。测量包含观察者开销。

## 检测对象与边界

| 来源 | 记录内容 | 解释 |
| --- | --- | --- |
| 应用及已登记服务 | CPU、工作集、可读取的私有内存、是否可读 | 进程 CPU 单核 100%；工作集含共享页，求和不是独占物理内存；PID 复用区分为不同代号 |
| 本实例容器 | 角色、运行/OOM、CPU、内存与上限、累计磁盘 I/O、PID 数 | 不采样其它实例；Docker 内存扣除部分缓存，I/O 不是带宽；无法读取不算零 |
| 宿主整体 | 全机 CPU、物理内存总量与已用 | 包含其它应用和观察者，不是 ENGE SPX 独占使用 |
| Docker Desktop / WSL2 | 可读取的进程 CPU 和工作集 | 共享 WSL 包含其它发行版与缓存，不与容器或主机内存相加；权限不足明确标记 |

总结只包含离散采样的最小值、中位数和最高采样值，可能错过间隔内的瞬时峰值。计数缺失、容器结果截断、后台进程不可读分别标为部分信息；只有成功查询后确认没有运行容器，才计为零。

资源查询先读取本地 Docker 上下文，允许绝对 Unix socket 和 Windows 本机命名管道，拒绝远程 SSH/TCP、远程管道和 Unix URI 的主机部分；[Docker 官方连接形式](https://docs.docker.com/reference/cli/docker/#daemon-socket-option)。不会启动 Desktop、切换上下文、调用 ready、续租、发起出口/浏览器网络探测或修改预算。独立 guard 保持原周期。

## 报告、体积和隐私

JSON schema=1，包含软件版本、系统类别、UTC 开始时间、手选标签、实际采样时点、结束原因、计数与总结。最长一小时、最多 720 个样本、完整报告不超过 4 MiB；到达限额会结束，不追赶漏掉的采样或并行启动更多查询。

使用字段白名单。PID、进程创建标识和容器 ID 转换为每份记录独立的代号；原始容器名、项目 hash、路径、代理地址/密码、命令行、环境变量、AI 输入、Cookie、账号和任意异常正文不写入报告。系统类别、UTC 时间和活动标签仍是环境信息；分享前可自行检查。没有自动上传。

中间样本以私有 `.partial` 文件写在你选定的输出文件旁，包含 JSON Lines 的 header/sample；正常完成原子保存最终 JSON 后删除中间文件。保存失败保留原输出及中间记录，并允许界面重新导出已采集的数据；故障不会停止安全监测。强制杀进程、断电或文件系统故障时，不保证最后一份未刷新的样本保留。中间记录不是账号备份，也不会被程序当作配置导入。

## 建议的实机验收

在同一设备、同一版本和类似网络/项目条件下分别记录：GUI 空闲、工作区空闲、真实 Claude/Codex 活动、浏览器活动、环境停止后的回收。需要 GUI 未启动的主机基线时使用 CLI，并保留“观察者仍运行”的区别。比较完整样本与不可用项，不把短期波动、共享缓存或不同活动标签解释成固定提速比例。
