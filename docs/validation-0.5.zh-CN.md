## 线路与落地分别核对

原生 Linux x64 集成使用自建回环 HTTP 线路和带认证的 SOCKS5 / HTTP 落地。落地使用宿主机无法解析的测试域名，由代理处理解析；两种落地都能通过完整出口检查。

设置一个与测得线路出口不同的预期 IP 后，检查失败并停止，落地连接计数没有增加。另一次测试通过更改已确认状态中的线路出口基线模拟变化，实际重新探测线路后停止环境；落地仍正常且其出口未改变。这些检查验证了独立的线路锁定逻辑，没有在真实用户的 v2ray 客户端中触发自动回退。

## 固定加密双跳

集成使用 SS AEAD 第一跳与 SOCKS5 落地，第一跳服务负责解析测试落地域名。网关配置没有 direct、selector 或 urltest 出站，落地必须 detour 到固定的加密第一跳。网关回环上的线路诊断端口可用，但从工作网络连接网关的 2082 端口失败，不能借诊断端口绕过落地。

随后停止第一跳服务，保留落地服务和网关外部网络。最终落地探测自身失败，环境检查也拒绝继续并停止，未出现绕过第一跳的成功连接。实际部署验证覆盖了 SS AEAD 第一跳；其他支持协议的导入与配置受单元检查覆盖，未逐一部署全部协议服务器。

## 环境变量不能绕过检测代理

Docker 可向容器注入代理和 `NO_PROXY` 设置。线路诊断现会清除这些环境变量，并明确使用网关回环代理；落地诊断创建时也清空两种大小写的 `NO_PROXY`。

实际测试关闭网关的外部网络，并确认其到 `1.1.1.1:443` 的直接 TCP 连接失败。加密第一跳仍可从内部网络到达并负责出网。向诊断进程注入 `NO_PROXY=*`、`no_proxy=*` 和指向不可用端口的 `HTTPS_PROXY` 后，两个 HTTPS 出口来源仍经固定线路返回一致结果。这项测试在绕过代理时无法完成。

第一次 0.5.2 构建在新增测试节点占用停止中网关地址时失败，发布被阻止。测试节点现固定在独立地址；上述最终构建完整重跑并通过。0.5.0 / 0.5.1 中间预览版已添加升级说明，其原有资产和标签没有被替换。
