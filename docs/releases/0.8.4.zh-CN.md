**启动热修复：旧浏览器容器阻止确认连接**

0.8.3 升级后，停止状态的旧浏览器仍可能被纳入新版本安全审计，显示“浏览器容器权限或 seccomp 策略不符合安全要求”，在替换浏览器之前就阻止启动。0.8.4 调整清理顺序：先停止环境并移除本实例已停止的浏览器容器，再检查出口和确认连接；按需启动的新浏览器仍必须通过全部沙箱检查。

- 浏览器 Profile、Cookie、Local Storage、下载、工具账号及项目可写层保留。只移除停止的浏览器实例，不删除卷，不强制移除正在运行的容器。
- 兼容 Docker 安全选项的 `=` / `:` 等效写法；缺失或关闭 no-new-privileges、冲突项、unconfined 和不同 seccomp 策略继续拒绝。
- 报错列出具体未通过的检查项，避免输出原始 inspect、环境变量、密码或令牌。
- 不增加容器权限，不使用无沙箱、DIRECT 或关闭 TLS 验证的回退。保留 0.8.3 的 Windows 当前用户 DPAPI 和 stdin / RAM 凭据传递。
- 不增加依赖，不改变镜像配方、凭据格式或用户配置；合格的 0.8.3 镜像可直接复用。第二批代理协议开发保持暂停，本版不混入未完成协议功能。

**更新方法：** 在旧版停止环境并退出旧窗口，完整安装或解压 0.8.4，以原 Windows 账户打开原数据目录，然后重新检查、确认出口。无需清空数据或重装 Docker。便携版应替换完整程序与 `_internal`，不要只替换单个 exe。

回归覆盖当前与旧版命名的升级确认、危险权限拒绝、真实 Docker 安全选项及内核 NoNewPrivs、旧浏览器替换后 Profile/下载保留，并沿用 renderer、登录回调、Cookie/Storage、断线阻断、续租、迁盘、Windows GUI/DPAPI 和安装卸载检查。测试范围与性能限制见[验证记录](https://github.com/engeeeee/ENGE-SPX/blob/v0.8.4-windows/docs/validation-hotfix-0.8.4.zh-CN.md)。实际 Docker Desktop 4.99.0 / WSL2 组合仍需用户机器复测。

这是未签名的 Preview 热修复；不承诺完整宿主隔离、匿名或真实性无法验证的指纹伪装。0.8.3 的显式凭据回滚流程继续适用，见[升级与恢复](https://github.com/engeeeee/ENGE-SPX/blob/v0.8.4-windows/docs/security-hardening.zh-CN.md)。
