# 资源占用与工作区预算

0.10.0 保留 Python/PySide6/Docker Desktop/WSL2。首次打开不会启动 Docker；旧配置和匹配镜像继续复用。

## 查看占用

在“资源与性能 → 占用概览”查看：应用控制进程、已登记的 guard/中转/显示服务、本实例 Linux 容器，以及可读取的 Windows Docker Desktop / vmmemWSL 进程。采样不读取命令行、环境变量、挂载内容或代理凭据，不查询其它实例的容器。

仅概览可见时每 10 秒采样，低资源模式每 15 秒；切换预算页、离开页面、最小化、隐藏到托盘或真正退出后停止新采样。一次在途采样有超时，不启动第二个。状态界面使用 3 秒刷新，低资源 5 秒，后台 10 秒；**独立 guard 仍按原周期复核出口、续租和异常停机**。

- 进程/容器 CPU 以单核 100% 计，多线程可超过 100%；主机整体 CPU 为全机百分比。第一次进程采样显示“采样中”，需要两次累计计数计算差值。
- Docker CLI 的 Linux 内存读数扣除部分文件缓存；进程工作集可能含共享页，不能简单求和视为独占物理内存。
- vmmemWSL 包含容器、其它发行版与缓存；通用 vmmem 可能对应其它共享虚拟机。它们不能与容器内存相加。
- 磁盘读写是累计 I/O，不是实时带宽。停止状态、计数不可用和 OOM 标记分别显示；工具子进程也可能 OOM，而容器 PID 1 仍存活。
- 无法读取某些系统进程时标明不可用，不请求管理员权限。不把 Linux CI 数据当作 Windows/WSL2 占用。

## 设置预算

在“预算设置”选择模式，再按需要修改 CPU、内存与当前项目预算。“保存资源设置”变更预算时先停止本实例工作区；请先保存工作，然后重新检查并确认出口。

| 环境 | 正常：CPU / 内存 | 低资源：CPU / 内存 |
| --- | --- | --- |
| 代理网关 | 不限 / 不限 | 1 核 / 256 MiB |
| 网络会话 | 不限 / 128 MiB | 0.25 核 / 128 MiB |
| CLI 项目默认值 | 不限 / 4096 MiB | 1 核 / 2048 MiB |
| Chromium | 不限 / 2048 MiB | 1 核 / 1024 MiB |

CPU 0 为不限。除网关可用内存 0 表示不限外，其它容器使用有限上限；下限分别为会话 64 MiB、项目/浏览器 512 MiB、有限网关 128 MiB。有限内存与交换合计设置为两倍内存上限，依赖 Docker/内核支持。上限不是预留，较低预算可能降低编译速度或导致 OOM，不保证提速或指定的全机占用。

在项目工作区选择目录后，可为该项目单独设置预算。实际保存时在工作线程解析真实目录，避免 GUI 输入路径时阻塞。其它项目使用各自覆盖值或公共 CLI 预算；多项目同时运行会累加。这是资源预算隔离，**不是账号或浏览器身份 Profile 隔离**。

资源更新发生在停止容器启动前，使用 Docker update，保留项目 ID、挂载、可写层和账号。更新不支持或返回值不符时保持停止。Docker 的 memory=0 不会清除已有上限，因此恢复不限网关时仅替换无用户数据的网关；项目容器不为此重建。不会执行 prune、WSL shutdown、关闭 Desktop 或修改全局资源配置。

## 浏览器与退出

正常模式保留启动工具时打开 Chromium 的行为；低资源模式默认关闭该选项。可以手动打开浏览器；显式“登录 Claude Code / Codex”仍准备浏览器。授权需要浏览器时请打开共享 Chromium 后重试，不会使用宿主浏览器或无沙箱模式。

“停止浏览器 · 保留 CLI”会停止 Chromium 和对应显示服务，网关、CLI 与 guard 继续运行；持久 Profile/Cookie/Storage 和下载卷保留。再次打开重新验证沙箱。X 隐藏到托盘，真正“退出软件”默认停止本实例；明确保留工作区的选项位于“更多”并需要确认。任务安全完成、后台收尾与停止失败重试见[退出流程](exit.zh-CN.md)。停止工作区后，WSL2 的缓存不一定立即归还 Windows。

## 配置、回滚与 CLI

`settings.json` 增加可选 `resources` 字段，schema=1。缺失时沿用旧默认，不重写现有设置；Windows 原设置仍由 DPAPI 保护。`resources-previous.json` 只备份上次有效资源设置，不包含代理、路径或账号；重复保存同一设置不会覆盖回滚记录。

```powershell
spx resources                       # 按需只读采样，不启动 Desktop
spx resources --show-settings       # 输出有效预算，不查询 Docker
spx resources --apply budget.json   # 停止本实例并保存 schema=1 预算
spx resources --restore             # 恢复上次预算，然后重新检查连接
spx stop-browser                    # 仅停止浏览器与显示服务
```

可以将 `--show-settings` 的 UTF-8 JSON 保存为模板再修改；导入严格校验版本、角色、项目标识和预算。旧版程序会忽略新增设置，但不能管理已应用的预算；降级前请先恢复正常预算、重新准备并停止，保留原数据备份。若只回滚配置，使用“恢复上次设置”，不要删除容器或卷。

实际测试、命令、测量范围和下一批任务见 [第三批交付记录](validation-resources.zh-CN.md)。
