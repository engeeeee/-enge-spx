# 智能剪贴板粘贴

此功能从 **0.14.0** 起提供；0.13.6 及以前的安装包不包含它。实际验证范围见[验证记录](validation-smart-clipboard.zh-CN.md)。

在 ENGE SPX 打开的 Claude Code / Codex **原来的 CLI 输入区**按 **Ctrl+V**。不经过另一层聊天框、上传页或文件选择器，不自动发送消息，不重启 CLI 或容器。

## 开启与使用

在偏好设置的“工作区终端”选择“自动（AI 智能粘贴）”或“智能粘贴终端”，保存，再打开 Claude Code / Codex。自动模式只为这两个 AI 工具选择智能终端，Linux shell 和登录窗口沿用原有自动选择。已经打开的外部终端不会被迁移或接管；在已有智能终端内的每次粘贴使用当前会话。

1. 普通文字直接 Ctrl+V；多行和 Unicode 经原生 bracketed paste 交给 CLI，不生成文件。
2. Win+Shift+S 截图后回到输入区 Ctrl+V，自动编码 PNG 并导入，等待 CLI 出现 `[Image #N]` 原生标记。
3. 在资源管理器复制 PNG/JPG/JPEG/WebP 文件后 Ctrl+V，也会作为图片附加。多张图片分别交给 CLI，逐张确认。
4. PDF、TXT、MD、JSON、CSV、DOCX、代码等普通文件以原件导入。保留原文件名提示；Claude 插入 `@绝对路径` 引用，Codex 插入可访问的绝对路径。
5. 可以在文字之间连续粘贴图片和文件。已有草稿不清空，键盘输入与附件按操作顺序交付，最后由你按 Enter。

**普通文件引用不是通用附件解析器。** Claude 的 Read 能力、权限规则和 PDF 限制仍然适用；Codex 对 PDF/DOCX 等格式可能需要项目内已有的解析工具。软件保留原件及扩展名，不伪造 PDF/DOCX 的原生附件标记，也不自动安装解析器。当前只把 PNG/JPEG/WebP 识别为视觉图片，其他格式按普通文件处理。

从 **0.14.2** 起，左键单击向已启用鼠标协议的 CLI 传递原生点击，直接定位输入光标；左键拖选则由终端选择文字，松开后自动复制到 Windows 剪贴板，不插入草稿。右键终端内容区会把剪贴板粘贴到当前 CLI 草稿，不自动发送。Shift+右键、菜单键或 Shift+F10 打开复制、粘贴、全选、取消选择和字号菜单。顶部不再显示复制按钮，窗口使用与主界面一致的自定义标题栏，支持拖动、最大化/还原及八方向缩放。

复制：拖选后松开即可复制，也可 Ctrl+Shift+C；有选择时 Ctrl+C 复制，没有选择时 Ctrl+C 保持中断。双击选择词语/路径。Ctrl+Shift+A 全选滚动历史和当前输出，普通 Ctrl+A 继续交给 CLI；Esc 取消选择。输出更新时选择快照保持稳定，避免复制到后来刷新的内容。Shift+拖动强制选择，Alt+拖动可交回 CLI 原生鼠标处理。菜单中的“拖选后自动复制”和“右键直接粘贴”可针对当前窗口关闭。

点击定位依赖 CLI 自己启用原生鼠标；已在 Codex 0.169.0 的多行/中文草稿实际验证，不会为不支持鼠标的程序模拟方向键。右键粘贴不改变已有光标位置；先单击定位即可在目标位置粘贴。

Ctrl++ / Ctrl+- 调整字号，Ctrl+0 还原，Ctrl+滚轮也可缩放，范围8–24 pt；不会重启 CLI。窗口保留暖深灰/陶土橙，正文遵循 CLI 实际 ANSI 16/256色、RGB真彩色、加粗/淡色、斜体、下划线和删除线；不为没有格式的输出虚构语法颜色。中文输入法、方向键、历史、Tab 和 Shift+Enter 保留。

0.14.3 起，Windows 10 智能终端绕过旧 ConPTY 的鼠标模式转换。单击定位仍需 CLI 自己支持鼠标，Codex 当前版本可用；未启用原生鼠标的程序不会被模拟方向键。输入法预编辑覆盖提示文字，确认后才进入草稿。右键粘贴包含末尾换行的文字也不会自动提交，仍需自己按 Enter。

浏览长对话请把鼠标放在对话输出区滚动；复制过内容也可以直接继续滚动，已复制内容仍在剪贴板，当前草稿不清空。完整对话由 CLI 管理，不受终端当前屏幕行数限制；Shift+滚轮用于终端自己的有限输出缓存（最多2000行），Ctrl+滚轮调字号。CLI 的全屏对话和普通 Shell 输出采用不同的历史机制；不要把2000行缓存当成 Codex 对话长度上限。

这是自有的轻量 VT 终端，未宣称具备 Windows Terminal 的全部扩展。OSC52 远程读写剪贴板不启用；依赖该协议的 CLI `/copy` 不保证写入 Windows 剪贴板，请使用终端选择复制。复杂扩展终端图形/完整 Kitty 键盘协议不在本批范围。工作区停止后自有终端窗口随连接结束关闭；单独更新/退出 CLI 仍保留原来的容器 shell。

## 终端与 CLI 兼容范围

| 方式 | 文字 | 截图/文件 Ctrl+V | 说明 |
| --- | --- | --- | --- |
| ENGE SPX 智能粘贴终端 | 原生 bracketed paste | 实现 | Qt 显示 + Docker 原始管道 + 容器内 Linux PTY，CLI 仍是原来的程序 |
| Windows Terminal | 保留原有行为 | 不接管 | 默认 paste 动作优先于子程序 Ctrl+V |
| PowerShell 7 / Windows PowerShell | 保留原有行为 | 不接管 | PowerShell 是 shell，实际快捷键还取决于承载它的终端 |
| 自定义终端 | 保留原有行为 | 不保证 | 不按品牌特判，不编辑第三方设置，不做全局键盘监听 |
| 在任意终端手动运行 `spx claude/codex` | 保留原有行为 | 不接管 | 仅 GUI 的受控 attach 会话接入剪贴板 |

从 **0.14.1** 起，不再以精确版本号拒绝用户更新，也不在每次导入额外启动 `--version`。当前会话必须在独立图片粘贴后产生新的原生 `[Image #N]` 标记，才继续下一项；不能只把文件复制成功当作完成。实际回归包括 Codex **0.169.0**、镜像内 Codex **0.167.0** 及 Claude **2.1.319**；其它版本仍需实际行为确认，不承诺所有未来版本。CLI 选择的模型必须支持图片，CLI 输入区需就绪；认证、信任或选择菜单不属于图片输入框。

状态栏只有观察到新增原生图片标记才报告交付完成。如果只显示路径或超时，会报错并取消失败前已排队的所有回车；请检查 CLI/模型，删除未附加的路径后重试。标记确认不等于真实模型理解测试，后者仍需实际发送验证。

## 数据、权限和缓存

- 读写项目：文件位于原项目绑定挂载内的 `.enge-spx-clipboard/<终端随机标识>/`。不会自动编辑你的 `.gitignore`，建议将 `.enge-spx-clipboard/` 加入忽略规则，避免把截图或导入文件提交。
- 只读项目：文件位于**这个项目容器**的 `/tmp/enge-spx-clipboard-<项目标识>/`；不写只读宿主目录，不使用共享账号 home，不增加挂载。容器删除/重建后临时附件会消失；停止再启动同一容器能否保留取决于其 `/tmp` 挂载方式，不能依赖其持久性。
- 不挂载剪贴板源文件所在目录。容器只得到用户主动选择的文件副本，不能由一个路径引用反向浏览宿主文件夹。
- 每次最多 32 个文件，普通文件每个 128 MiB、图片每个 32 MiB、批次合计 256 MiB、图片最多 4000 万像素；格式解码器自身的内存限制也适用。仅支持本机普通文件，不接收目录、设备、最终符号链接、网络路径和 NTFS 数据流。
- 每项目容器/项目缓存上限 1 GiB、8192 个文件，超限拒绝新导入。关闭终端之后至少保留七天；后续同项目粘贴时，只清理已关闭、作用域相同且过期的缓存，活动终端的文件不清理。
- 如需立即清理，先保存并关闭引用这些附件的 CLI 会话，再在读写项目中删除对应缓存目录。只读项目的缓存属于容器临时资料；不要为清理附件重建有未保存数据的容器。
- 本地 `data/clipboard-sessions` 仅保存不含内容的清理作用域与 OS 锁记录，不保存剪贴板历史；不应把它当作附件备份。

剪贴板仅在该终端接到主动粘贴时读取。文件复制在后台执行；失败保留草稿，不自动重试、发送或转为直连。复制过程中剪贴板变化会取消对应快照，避免粘贴错误内容。安全边界与[工作区身份](workspaces.zh-CN.md)、[隔离模型](security-model.zh-CN.md)保持一致。
