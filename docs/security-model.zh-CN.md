# 隔离与安全模型

ENGE SPX 的目标是减少 AI 工具、浏览器和工作流对 Windows 日常环境的直接接触，同时让工作区网络出口可配置、可核对。这里区分文件和进程隔离、网络路径控制，以及仍然需要信任的部分。

## 实际隔离了什么

| 层面 | 实现 | 作用与边界 |
| --- | --- | --- |
| 运行环境 | 工具、浏览器和网关运行在 Docker Linux 容器；Windows 通常由 Docker Desktop / WSL 2 承载 | 工具的 Linux 依赖与 Windows 日常应用分开；它不是单独安装的 Windows 虚拟机 |
| 文件访问 | 只给项目容器挂载选中的项目；浏览器不挂载项目目录或工具账号卷 | 减少无关本机文件的暴露，但选中项目仍是读写共享 |
| 管理权限 | 工具容器不挂载 Docker 管理接口；容器移除 Linux capabilities，启用 `no-new-privileges` | 限制容器内提权与直接管理宿主 Docker 的能力，不能保证抵御内核或容器逃逸漏洞 |
| 网络空间 | 工作容器使用内部网络和受控会话网络空间；网关承担外联 | 正常配置下，工作容器没有直接公网路由；不靠仅设置应用代理变量实现隔离 |
| 网关 | 只读根文件系统、只读配置挂载；诊断入口仅监听自身回环 | 减少意外改动；工作容器不能借线路诊断入口跳过落地 |
| 浏览器资料 | 独立的容器 Chromium profile 和持久卷 | 不自动继承 Windows 本机浏览器登录态；工作区内多个项目会共享该 profile |

上述行为由代码、单元测试和真实 Linux Docker 集成检查覆盖，详见 [开发说明](development.md)和版本验证记录。它们不是第三方安全审计结论。

## 代理路径控制

推荐模式由软件配置固定的“加密线路 → 落地代理”，没有 DIRECT、自动测速或故障回退作为备用。第一跳认证或连接失败时，这条路径会失败，不会由本软件改成直连。落地域名在第一跳内处理；线路服务器的 IPv4 由用户提供，原 TLS 名称和校验保留。

程序分别检测线路与落地的出口，确认前重新核对，运行后持续监测。检测到已确认的出口变化、拓扑变化或连接故障，会停止本环境。监测有约 30 秒周期和请求超时，不能承诺瞬时发现 IP 变化。该模式不保证线路服务商的服务器侧行为。

兼容模式把连接交给本机 v2ray 等代理。外部代理仍可能按目标决定 DIRECT 或其他路径；检测服务的出口正确，不能证明每个目标都经过同一线路。软件不会自动重写 Windows 系统代理、v2ray 配置或防火墙。

运行环境、订阅下载和 Docker 镜像拉取属于安装流量，不等同于工作区流量；范围详见 [线路保护](line-protection.zh-CN.md)。

## 必须保留的信任边界

- **项目文件可读写。** 工具能读取其中密钥、修改代码和删除文件。容器无法替代项目备份、Git 和最小目录授权。
- **宿主机仍是信任根。** 管理员、恶意宿主程序和 Docker 管理端能接触容器与数据；本机已被控制时，容器不能保护凭据。
- **容器共享 Linux 内核。** 不能把容器等同于运行任意恶意程序的专用安全沙箱；Docker / WSL 漏洞仍可能影响边界。
- **Chromium 当前使用 `--no-sandbox`。** 浏览器自身沙箱未启用，仍依赖外层容器隔离。不要据此承诺抵御恶意网页或浏览器漏洞。
- **配置中的代理凭据当前未接入 Windows 凭据库加密。** 私有目录、Docker 账号卷、浏览器 profile 都需要妥善保管和备份。
- **账号不按项目隔离。** 工具账号在项目间共享，浏览器也使用共享持久 profile。切换项目不等同于切换身份。
- **代理不提供匿名保证。** 线路、落地、检测服务及目标平台分别有可见信息；出口可核对不代表不会被关联、限制或封号。

与直接在 Windows 本机运行工具相比，ENGE SPX 能减少无关目录、日常浏览器资料和本机依赖的直接暴露，并给工作区增加受控出口和异常停止机制。它不能消除被共享文件、已授权账号、供应链、宿主机失陷和服务商带来的风险。

当前版本为未签名 Preview，未完成独立安全审计，也没有在用户的 Docker Desktop、v2ray、Pebrel 实机组合上完成全流程交互验收。发现漏洞请按 [安全报告说明](../SECURITY.md)处理，避免公开凭据或未修复漏洞细节。
