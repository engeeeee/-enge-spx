# 存储位置与第三方终端

适用于 ENGE SPX 0.4.0 Preview。在“偏好设置”中完成配置。

## 使用 Pebrel

1. 在“工作区终端”选择 **Pebrel**。安装在常见目录或已加入 PATH 时，可点击“检测终端”；便携版或自定义安装目录请点击“选择 exe”，选中 `pebrel.exe`。
2. 点击“测试终端”。会在所选终端内打开本地 PowerShell 测试窗口，不需要连接代理、登录账号或启动 Docker 工作区。
3. 确认可用后点击“保存终端设置”。下次打开 Claude Code、Codex、Linux 终端或登录窗口时生效，无需重新建立代理连接。

自动选择按 Pebrel、Windows Terminal、PowerShell 7、Windows PowerShell 的顺序检测。手动选定的终端找不到时会提示，不会静默切换到其他终端。

Pebrel 接收项目工作目录、窗口标题和 Docker 工作区命令，工具本身仍在 Linux 容器内运行。这里选择的是 Windows 上显示工作区的终端程序。`spx claude` 等命令行操作继续使用调用它们的终端。

“自定义程序”支持可直接启动命令的终端 exe。参数示例：

```text
--working-directory "{project}" --title "{title}" --hold -e {command}
```

这是 Pebrel 风格的示例。其他终端的参数名称请使用其官方说明。

| 占位符 | 用途 |
| --- | --- |
| `{project}` | 本机所选项目的完整路径 |
| `{title}` | 工作区窗口标题 |
| `{command}` | 必须独立出现一次，插入完整 Docker 命令及各个参数 |

参数按 Windows 双引号规则解析，不会自动拼接成 CMD 命令。exe 路径使用上方独立输入框，不要填进参数。含空格的参数请加双引号。

## 占用空间的位置

| 数据 | 内容 | 迁移入口 |
| --- | --- | --- |
| 应用数据 | 配置、代理信息、日志、运行环境下载缓存及断点文件 | 应用数据与下载缓存 |
| Docker 数据盘 | 镜像、构建缓存、容器可写层、工具账号与浏览器数据卷 | Docker 数据盘迁移助手＋Docker Desktop |
| 项目目录 | 选择的真实项目文件 | 在 Windows 中自行整理，再重新选择项目 |
| 程序目录 | ENGE SPX 的 exe 和运行库 | 安装时选择目录，或将完整免安装包放在目标盘 |

应用数据和 Docker 数据盘使用不同的专用文件夹，例如 `D:\ENGE-SPX\data` 和 `D:\DockerData`。不要直接选择整块磁盘，也不要选择已有项目目录。

## 迁移应用数据与下载缓存

1. 保存工作。在“应用数据与下载缓存”选择或输入专用空目录。
2. 点击“检查并迁移应用数据”，核对当前路径、目标路径、大小和可用空间，再确认。
3. 等待复制和校验完成。软件会停止本工作区和后台服务，保留安装标识，切换默认位置，再清理原目录中已校验的副本。
4. 当前位置会更新为新目录。重新检查并确认连接，继续使用工作区。

后续运行环境下载进入新目录，已有 `.part` 和续传元数据一起迁移。Windows 下会先为目标设置当前用户、SYSTEM 和管理员的访问权限，再写入配置。请使用支持 Windows 文件权限的本地磁盘。

原目录保留很小的 `relocated.json` 和锁文件，让旧的 `--data` 启动方式能找到新位置；LocalAppData 下的 `ENGE-SPX-location.json` 记录默认位置。少数被其他进程占用的旧文件无法删除时，会在新目录的 `storage-migration.json` 中记录。

迁移不会重新安装镜像或项目容器。下次检查连接时，只重建需要更换配置挂载位置的已停止网关；项目容器的可写层、工具账号和浏览器数据卷继续使用原资源。

## 迁移 Docker Desktop 数据盘

Docker Desktop 的[官方 WSL 2 说明](https://docs.docker.com/desktop/features/wsl/#turn-on-docker-desktop-wsl-2)提供了通过 Settings → Resources → Advanced 更改位置的入口。迁移整个 Docker 数据盘会影响本机其他软件的 Docker 工作，请先保存这些工作。

1. 点击“检测存储位置”。软件只读取 Docker 设置和数据盘文件；若不能确定实际位置，会明确显示为默认候选位置。
2. 选择专用空目录，例如 `D:\DockerData`，点击“准备迁移”。ENGE SPX 停止自己的工作区，记录现有镜像、容器和数据卷，将目标路径复制到剪贴板，并打开 Docker Desktop。
3. 在 Docker Desktop 点击设置齿轮，进入 **Resources → Advanced → Disk image location**，选择同一个目标目录，点击 **Apply**；有的版本显示 **Apply & restart**。
4. 等待 Docker 完成迁移并恢复运行。返回 ENGE SPX，点击“核验迁移结果”。核验需要目标位置已写入 Docker 设置、该处存在 VHDX，以及原容器、镜像和数据卷都能找到。
5. 重新检查并确认连接。

软件不会修改 Docker 的设置 JSON、注销 WSL 发行版、执行 prune，或自行移动正在使用的 VHDX。Docker Desktop 的设置格式不是稳定公开接口；若版本变化导致位置无法识别，核验会提示“尚未确认”，不会报告成功。原资源存在仅代表资源可见，不等于逐字节校验整个 Docker 数据盘。

## 未完成时如何处理

- **应用数据复制或校验失败**：默认位置不切换，原数据保留。检查目标盘空间、权限和文件占用，再重试。若已生成完整目标副本但写入切换记录失败，先保留原目录，根据错误中路径检查副本，避免重复覆盖。
- **迁移后磁盘未连接**：连接原目标盘后重开软件。软件会报错并保留位置记录，不会自动创建一个空的新环境。可用 `spx --data 完整路径 status` 指定已确认的现有数据目录。
- **旧文件清理失败**：迁移后的目录已经生效，先正常使用新目录；根据 `storage-migration.json` 核对旧文件，再在关闭占用进程后清理。
- **Docker 仍在原位置**：回到 Docker 设置完成 Apply，等待其恢复运行后再核验。ENGE SPX 的“准备迁移”只创建计划，不代表数据盘已经移动。
- **迁移后找不到账号卷或镜像**：先在 Docker Desktop 确认选择了原数据盘并完成迁移。暂勿重新安装环境或创建同名卷，以免把空环境误当成原环境。
