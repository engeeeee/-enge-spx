# 关闭窗口与退出软件

规则是：**X 隐藏到托盘；真正退出默认停止本实例工作区。** 0.12.1 增加可选联合退出，默认仍保留 Docker Desktop。

| 操作 | 结果 |
| --- | --- |
| 标题栏 X | 隐藏界面，托盘保留；CLI、浏览器和安全监测继续运行 |
| 托盘单击/双击、“显示主窗口”或重新打开软件 | 恢复同一窗口，不重复启动工作区 |
| 托盘退出、Ctrl+Q、设置页退出按钮 | 安全结束当前操作、撤销授权、停止本实例容器，等待后台服务退出并核验及记录保存；若已启用联合退出，再正常关闭 Desktop，最后关闭界面与托盘 |
| 托盘“更多 → 保留工作区，仅退出界面…” | 明确确认后仅关闭界面和托盘；正在运行的工作区与独立 guard 保留，需重新打开软件管理 |
| 系统托盘不可用时点击 X | 使用默认停止并退出，避免留下无法访问的隐藏界面 |

首次隐藏时在系统支持的情况下显示本会话提示；托盘菜单和提示文字反映当前工作区状态。退出会结束正在运行的工具命令，请先保存终端和浏览器中的工作。项目文件、账号、持久浏览器资料及已下载进度保留。

重新打开软件时，由已有进程通过 Qt 恢复窗口和输入状态，避免仅在 Windows 层显示窗口后，界面仍被 Qt 视为隐藏，造成快捷键或资源页面不响应。

## 可选同时关闭 Docker Desktop

Windows 用户在 **偏好设置 → 启动行为** 勾选 **退出时关闭 Docker Desktop**，再点击 **保存退出偏好**。只勾选而未保存不生效；托盘和设置页退出按钮会反映已经保存的选择。

此选项会正常关闭整个 Docker Desktop，**其它 Docker 容器也会中断**。X 隐藏到托盘、显式“保留工作区退出”、普通“停止环境”以及预算/身份变更都不触发联合关闭。不会启动尚未运行的 Desktop 来完成退出，不使用 `--force` 或全局 `wsl --shutdown`，不关闭其它 WSL 发行版、本机代理或删除镜像/容器/数据卷。

关闭 Desktop 不等于清理磁盘、压缩虚拟盘或保证共享 WSL2 缓存立即归零。磁盘位置仍由 [存储迁移](storage-terminal.zh-CN.md) 管理。

采用 [Docker 官方 stop](https://docs.docker.com/reference/cli/docker/desktop/stop/) 的 `--detach` 正常关闭请求，让命令先返回，再独立核对 [status JSON](https://docs.docker.com/reference/cli/docker/desktop/status/) 明确为 stopped。整个流程最多等待 60 秒；关闭期间状态接口短暂不可读时继续有界核验，不能把错误当作停止。只有旧 CLI 明确拒绝 `--detach` 时，才回退到有界的普通同步关闭；不会启用 `--force`。

若你先手动关闭 Docker Desktop，再退出 ENGE SPX，软件先核实选定 context 确实指向本机 Desktop Linux 命名管道。管理状态明确为 stopped 时按原流程收尾。0.13.3 补充处理连后台管理接口也已退出的情况：只有本机设置明确为 WSL2、完整进程枚举确认没有 Desktop 后台、Win32 明确报告引擎管道不存在、已注册的 `docker-desktop` 不在 WSL 运行列表，且进程和管道复查仍一致时，才接受独立停止证据。

0.13.4 补充处理关闭过渡期：管理状态为 stopping 时，在包含上下文/状态查询的 12 秒预算内继续观察；管理接口消失后，在剩余预算内最多等待 8 秒，重复同样的完整进程、管道及 WSL 证据。管道先消失而进程/发行版稍后退出，不再仅因第一份过渡快照立即失败。最终仍需完整停止证据；running、starting、paused 和未知/超时不视为已停。可选联合关闭仍受原 60 秒总时限约束。

0.13.5 修复 Windows 管理命令超时后，子插件持有捕获管道而拖延返回的问题。管理输出改用限量私有临时文件，避免等待子插件的 EOF；只回收本次命令行进程。工作区离线核验的整体预算为 20 秒，其中保留最多 8 秒给完整进程/管道/WSL 核验，管理查询不能全部用完。诊断明确区分管理查询超时、核验预算耗尽与非 Windows 平台，取消含混的 `unsupported_or_expired`。联合关闭仍是 60 秒总预算，所有停止证据要求保持不变。

0.13.6 修复默认设置的兼容性：Docker 的 WSL2 默认值为 true，用户设置可以省略该开关。软件只读检查当前/旧版用户设置、安装设置和管理策略；当前文件损坏不改读旧文件，不把文件不存在或权限不足当作默认值。明确的用户选择优先于安装默认；策略和其它层存在无法离线确定的冲突时保持未知。Windows 环境目录变量缺失时使用系统当前用户目录查询。

隐含 WSL2 选择还需核实当前用户 `docker-desktop` 的注册 Version=2，并确认 Desktop 进程不存在、管道明确不存在、WSL 中没有运行的 Docker 发行版，随后重读配置/注册及复查进程/管道。不会修改开关或注册表，不将 Hyper-V / Docker VMM / Windows containers 当作 WSL2；未知后端仍需管理接口明确停止。报告以 `default_wsl2`、`user_disabled`、`user_settings_missing`、`conflicting_policy` 等固定分类说明原因；显式配置拒绝不再每 250 ms 重复相同检查，短暂读取/共享失败仍有界重试。

随后撤销租约、清理运行时凭据引用、等待本实例后台服务退出并再次核验，无需为退出重新打开 Docker。WSL 查询只列出已注册/运行的发行版，不启动发行版，不执行终止或全局关闭。其它 WSL 发行版可以继续运行；原始发行版名称、设置文件内容及命令错误不写入日志。管道不存在、普通连接失败、权限不足、部分进程列表、远程/通用 context 或未知状态本身仍不能作为停止证据。该独立路径不适用于 Hyper-V 或无法确认后端类型的安装，管理接口正常时仍沿用原核验方式。

偏好存于当前数据目录的非敏感 `exit-preferences.json`（schema=1）；旧数据缺失时关闭，旧程序忽略该文件。取消勾选并保存即可回滚，不需要修改代理、账号或重建镜像。损坏/未知版本不能启用该功能；保存失败仍使用旧值，并取消已排队的退出以避免执行旧的全局选择。

## 操作进行中

退出请求只接收一次，之后不再启动新任务。可取消的下载/准备会安全暂停，保留进度；不可取消的步骤先完成。退出等待期间不会再弹出连接确认或启动其它任务；数据迁移已提交时仍完成新路径接管，然后在正确位置停止工作区。

界面显示等待、停止、后台服务收尾等进度。资源采样收到取消标记，在途查询完成或超时后不再发起下一条命令；关闭界面前等待采样收尾。不会直接终止正在写入数据的 GUI 工作线程。

## 停止失败

0.13.4 的退出失败弹窗直接提供 **复制诊断信息**，不需要先关闭弹窗或寻找日志。摘要包含实际运行版本和固定核验阶段，复制时不查询 Docker；配置暂不可读也能复制最小版本与本次退出报告。复制后按钮会确认剪贴板内容；暂不可用时显示提示。

每次退出失败还会尝试原子保存当前数据目录的 `logs/exit-diagnostics.json`；最多保留最近 64 项检查，不包含原始命令输出、异常消息、发行版名称、用户路径或代理数据，不自动上传。写入失败仍可从内存复制，不能覆盖原退出失败。报告只供诊断，不参与连接或停止授权。


停止、后台收尾或容器核验失败时，保留并恢复主窗口，显示原因，允许重试，不显示为已退出。如果已有运行环境但找不到 Docker CLI，会先撤销本实例授权并报告无法核验，不会声称容器已停止。退出流程不为了停止而自动启动 Docker Desktop。

如果工作区已经核验停止，仅 Desktop 的关闭确认失败，界面提供 **重试确认 Docker Desktop**、**仅退出 ENGE SPX** 和 **返回软件**。返回为默认选项。一次性“仅退出”只跳过本次 Desktop 等待，不改变已保存的联合关闭偏好，也不声称 Desktop 已关闭；先前发出的正常关闭请求可能仍在执行。

重试或一次性退出只在没有后续 Engine 操作、运行记录仍明确为停止时复用原停止结果；新工作区操作、状态变化或记录不可读会使结果失效，必须重新停止并核验。工作区本身停止失败时不提供这条快捷退出路径。仍可在设置中取消联合关闭并保存，使之后的正常退出都保留 Desktop。

如确实只想关闭界面，可明确选择保留工作区的选项；该选择不会替你启动或重新确认连接。普通 X 隐藏不触发停止；CLI 工具命令自然结束也不自动停止其它工作区。

默认流程只管理当前数据目录所属实例。只有明确启用的联合退出会关闭整个 Docker Desktop；安全监测和无 DIRECT 回退机制保持原有规则。不执行 prune 或删除项目、账号/Profile 卷。原始功能见 [交付验证](validation-desktop-exit.zh-CN.md)，本次改动见 [0.13.6 验证](validation-0.13.6.zh-CN.md)。
