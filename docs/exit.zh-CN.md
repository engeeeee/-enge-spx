# 关闭窗口与退出软件

规则是：**X 隐藏到托盘；真正退出默认停止本实例工作区。** 0.12.1 增加可选联合退出，默认仍保留 Docker Desktop。

| 操作 | 结果 |
| --- | --- |
| 标题栏 X | 隐藏界面，托盘保留；CLI、浏览器和安全监测继续运行 |
| 托盘单击/双击、“显示主窗口”或重新打开软件 | 恢复同一窗口，不重复启动工作区 |
| 托盘退出、Ctrl+Q、设置页退出按钮 | 安全结束当前操作、撤销授权、停止本实例容器，等待后台服务退出并核验及记录保存；若已启用联合退出，再正常关闭 Desktop，最后关闭界面与托盘 |
| 托盘“更多 → 保留工作区，仅退出界面…” | 明确确认后仅关闭界面和托盘；正在运行的工作区与独立 guard 保留，需重新打开软件管理 |
| 系统托盘不可用时点击 X | 使用默认停止并退出，避免留下无法访问的隐藏界面 |

首次隐藏时在系统支持的情况下显示本会话提示；托盘菜单和提示文字反映当前工作区状态。退出会结束正在运行的工具命令，请先保存终端和浏览器中的工作。项目文件、账号、持久浏览器资料及已下载进度保留。

重新打开软件时，由已有进程通过 Qt 恢复窗口和输入状态，避免仅在 Windows 层显示窗口后，界面仍被 Qt 视为隐藏，造成快捷键或资源页面不响应。

## 可选同时关闭 Docker Desktop

Windows 用户在 **偏好设置 → 启动行为** 勾选 **真正退出时同时关闭 Docker Desktop**，再点击 **保存退出偏好**。只勾选而未保存不生效；托盘和设置页退出按钮会反映已经保存的选择。

此选项会正常关闭整个 Docker Desktop，**其它 Docker 容器也会中断**。X 隐藏到托盘、显式“保留工作区退出”、普通“停止环境”以及预算/身份变更都不触发联合关闭。不会启动尚未运行的 Desktop 来完成退出，不使用 `--force` 或全局 `wsl --shutdown`，不关闭其它 WSL 发行版、本机代理或删除镜像/容器/数据卷。

关闭 Desktop 不等于清理磁盘、压缩虚拟盘或保证共享 WSL2 缓存立即归零。磁盘位置仍由 [存储迁移](storage-terminal.zh-CN.md) 管理。

采用 [Docker 官方 stop](https://docs.docker.com/reference/cli/docker/desktop/stop/) 的同步正常关闭，随后核对 [status JSON](https://docs.docker.com/reference/cli/docker/desktop/status/) 明确为 stopped；连接失败和错误返回不能当作停止证据。旧版本不支持管理接口、权限不足或超时时保留窗口。请处理 Desktop 提示后重试，也可取消联合关闭并保存，再仅退出工作台。

偏好存于当前数据目录的非敏感 `exit-preferences.json`（schema=1）；旧数据缺失时关闭，旧程序忽略该文件。取消勾选并保存即可回滚，不需要修改代理、账号或重建镜像。损坏/未知版本不能启用该功能；保存失败仍使用旧值，并取消已排队的退出以避免执行旧的全局选择。

## 操作进行中

退出请求只接收一次，之后不再启动新任务。可取消的下载/准备会安全暂停，保留进度；不可取消的步骤先完成。退出等待期间不会再弹出连接确认或启动其它任务；数据迁移已提交时仍完成新路径接管，然后在正确位置停止工作区。

界面显示等待、停止、后台服务收尾等进度。资源采样收到取消标记，在途查询完成或超时后不再发起下一条命令；关闭界面前等待采样收尾。不会直接终止正在写入数据的 GUI 工作线程。

## 停止失败

停止、后台收尾或容器核验失败时，保留并恢复主窗口，显示原因，允许重试，不显示为已退出。如果已有运行环境但找不到 Docker CLI，会先撤销本实例授权并报告无法核验，不会声称容器已停止。退出流程不为了停止而自动启动 Docker Desktop。

如果工作区已经核验停止，仅 Desktop 的关闭确认失败，界面会区分这两种状态。重试或取消联合关闭时，在没有后续 Engine 操作且运行记录仍为停止的条件下保留原停止结果，避免为退出而重新启动 Docker；任何新的工作区操作或非停止状态都会使该结果失效。

如确实只想关闭界面，可明确选择保留工作区的选项；该选择不会替你启动或重新确认连接。普通 X 隐藏不触发停止；CLI 工具命令自然结束也不自动停止其它工作区。

默认流程只管理当前数据目录所属实例。只有明确启用的联合退出会关闭整个 Docker Desktop；安全监测和无 DIRECT 回退机制保持原有规则。不执行 prune 或删除项目、账号/Profile 卷。实际检查与实机范围见 [交付验证](validation-desktop-exit.zh-CN.md)。
